# EE 230 animated lessons — Tiers 2 to 5

Continues `2026-09-03-ee230-lessons-design.md`, which built the three-view kit and the
eight Tier 0–1 lessons. This spec covers the remaining course: ideal op-amps, real
op-amps, comparators and waveform generation, and diodes. Each tier is built by its own
agent on the shared kit, in parallel, and each agent owns only its own files.

The course: EE 230, Iowa State (Geiger, Sedra/Smith). The public site's labs give the
canonical sequence and are linked per tier below. The student is four semesters away from
circuits, so each lesson names what it shows in plain words before it uses the term.

## The contract every tier keeps

**Three views, one clock, one layout.** Every lesson uses `eeLesson` from
`src/lessons/ee/kit.ts` and the fixed `LAYOUT`: schematic top-left, equations bottom-left,
scope top-right, transfer view bottom-right. Whatever animates in the scope animates in the
transfer view at the same instant. Read `theoremOne.ts` and `rcFilters.ts` first; they are
the exemplars, and every existing lesson follows their shape exactly.

**The kit is composed, not forked.** `scopePaneRaw`, `bodePane`/`bodePaneMulti`,
`transferCurvePane`, `sPlanePane`, `phasorPane`, `equationPane`, `makePlane`, and the
helpers in `util.ts` (`fade`, `fadeBetween`, `stepTrack`, `valueTrack`, `chirp`, the unit
formatters). A tier may add a pane to `kit.ts` only by **appending** a new exported
function; existing functions are not edited, because the other tiers depend on them.

**Schematics wire only to reported terminals.** Compose the symbols in
`src/physics/circuit.ts` (`opAmp` reports `inMinus`, `inPlus`, `out`; every two-terminal
symbol reports `a` and `b`; `ground`; `diode`; `wire({ current })`). Every junction where
three conductors meet is an explicit shared endpoint. Each tier's schematics go in its own
file (`opAmpSchematics.ts`, `diodeSchematics.ts`), and each must pass
`checkConductorConnectivity` — which only judges a scene carrying electrical notation, so
label components with real values (`R = 10 kΩ`), not placeholders.

**Files a tier owns.** Lessons: `src/lessons/ee/<lesson>.ts`. Schematics: its own file.
Registration: `src/catalog/ee/tier<N>.tool.ts`, exporting `tier<N>Tools` built with
`lesson()` from `define.ts`. Routing phrases: `src/lessons/ee/phrases.tier<N>.ts`,
exporting `TIER<N>_PHRASES`. Tests: `test/unit/ee-tier<N>.test.ts`. Nothing else is
touched: not `lessons.tool.ts`, not `lessonRouting.ts`, not another tier's files, not the
existing lessons.

**Plain-text labels use `LABEL_FONT` (Inter).** The theme font lacks ω, θ, φ and
subscripts, and no pinned font has ∠ at all. Greek in plain text is fine in Inter; ∠ goes
only inside KaTeX (`equationPane`), and plain text writes `arg T`. A text node must never
have empty `text` — the validator rejects it.

**Every lesson is tested on its physics, not just that it renders.** The `isLesson`
harness from `ee-tier1.test.ts` (valid, deterministic, 1280×720, 15–90 s, every promised
view present, narration non-overlapping, catalog-reachable) plus assertions on the numbers
the lesson shows: a counter reads the value the equation predicts, a trace starts when its
beat does, a dot lands where the theory says.

**Every lesson is rendered and looked at.** Frames at two or three beats, via
`renderFrame(spec, t * fps).toPNG()` into the scratchpad, then opened with Read. Tests
cannot see tofu glyphs, a label on top of a part, or two tick labels colliding; the
previous tiers found all three that way. Fix what the frame shows before committing.

**Caveats are reported, not buried.** The agent's final message carries a `CAVEATS`
section listing every approximation, every deliberate simplification, and every known
false positive or gap. The integrator appends them to `docs/EE230_LESSONS.md`. Agents do
not edit that file themselves.

## Tier 2 — op-amps, ideal (weeks 4–5)

Labs: [Op Amp Applications](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%205%20Fall%202006%20Op%20Amp%20Applications.pdf),
[Linear Op Amp Applications](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%206%20Spring%202010%20Linear%20Op%20Amp%20Applications.pdf).
Reference: Sedra/Smith ch. 2.

Schematics file: `opAmpSchematics.ts`, exporting at least `invertingStage`,
`nonInvertingStage`, `summingStage`, `integratorStage` (each composing `opAmp` +
resistors/capacitor + ground, wired to terminals, with `current`). **Tiers 3 and 4 reuse
this file**, so its exports are the contract; keep them general (labels and element kinds
as options).

| lesson | what the student sees |
|---|---|
| `ee.opAmpRules` | The bare op-amp: gain A drawn as a counter climbing to a huge number, then the two ideal rules appearing as the feedback loop closes — no current into either input, and v− dragged to v+. The transfer view shows v_out vs (v+ − v−) as an almost vertical line: why any finite output means the inputs are equal. Narrate "virtual short" and "virtual ground" in plain words. |
| `ee.invertingAmp` | Inverting stage, gain −R_f/R_in. Scope: input sinusoid and the inverted, scaled output on one time axis; a counter reads the gain. Transfer view: V_out vs V_in as a straight line of negative slope with a dot tracking. Then change R_f (stepTrack) and the slope and the output height change together. |
| `ee.nonInvertingSumming` | Non-inverting stage, gain 1 + R_f/R_g, input and output in phase; then the summing amplifier: two inputs of different frequency on separate planes and their weighted sum on a third — the scope makes "sum" literal. Counters for each weight. |
| `ee.integrator` | The original brief that failed: R in, C in feedback, square wave in → triangle out. Scope: square input and the ramping output, with the ramp's slope read live as −V_in/(RC). Then swap to the differentiator (C in, R feedback): triangle in → square out. This is the lesson the whole project started from; make it the best one in the tier. |

## Tier 3 — op-amps, real (week 6)

Lab: [Measurement and Management of Op Amp Parameters](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%207%20Spring%202010%20Measurement%20and%20Management%20of%20Op%20Amp%20Parameters.pdf).
Datasheets on the course site: 741, LF356, LMC660. Reference: Sedra/Smith ch. 2.6–2.8.

Reuses `opAmpSchematics.ts` from Tier 2 (do not duplicate it). Each lesson opens with the
ideal behaviour from Tier 2 and then shows exactly where it breaks.

| lesson | what the student sees |
|---|---|
| `ee.saturation` | Inverting stage with the supply rails drawn. Input amplitude grows over the beat (a rising envelope); the output follows until it hits ±V_sat and flattens. Transfer view: the straight line with the rails clipping it, the dot running into the rail and stopping. Counters for V_in peak and V_out peak; the moment they stop tracking is the lesson. |
| `ee.slewRate` | A square wave in. At low frequency the output is a square wave; as the frequency rises the output cannot get there in time and becomes a trapezoid, then a triangle, at the slew rate in V/µs. Scope: the ramps drawn with the slope read live. Name the full-power bandwidth. |
| `ee.gainBandwidth` | Open-loop gain A(jω) as a Bode plot with its single pole, and the closed-loop gain of three stages (gains 1, 10, 100) overlaid: each is flat to a bandwidth of GBW/gain and then rides down the open-loop line. Dots on the shared sweep. A counter reads the gain-bandwidth product staying constant while gain and bandwidth trade. |

## Tier 4 — comparators, hysteresis, waveform generation (weeks 7–9)

Labs: [Nonlinear Op Amp Applications](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%207%20Fall%202006%20Nonlinear%20Op%20Amp%20Applications.pdf),
[Comparator Applications](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%208%20Fall%202006%20Comparator%20Applications.pdf).
Datasheet: LP339. Reference: Sedra/Smith ch. 18 (Sedra/Smith 5e: 13).

Reuses `opAmpSchematics.ts` for the op-amp symbol; adds what it needs to its own
`comparatorSchematics.ts`.

| lesson | what the student sees |
|---|---|
| `ee.comparator` | Open-loop op-amp as a comparator against a threshold V_ref. A slow, slightly noisy input crosses the threshold; the output snaps between the rails and chatters on every crossing. Transfer view: the near-vertical step at V_ref with the dot flicking across it. The chatter is the problem the next lesson solves. |
| `ee.schmittTrigger` | Positive feedback adds hysteresis: two thresholds V_TH and V_TL. Same noisy input, now a clean output. Transfer view: the hysteresis loop traced live as the dot goes round it — up one edge, across, down the other. Counters read the two thresholds from R_1, R_2 and V_sat. |
| `ee.relaxationOscillator` | Schmitt trigger plus an RC: the capacitor charges toward the rail until it hits V_TH, the output flips, it discharges to V_TL, it flips back. Scope: the capacitor's exponential sawtooth and the square output, on one time axis. The period formula built from τ and the thresholds, with the counter reading the period the scope shows. |

## Tier 5 — diodes and rectifiers (lab)

Lab: [Diodes, Rectifiers and Data Converters](https://class.ece.iastate.edu/ee230/Labs/EE%20230%20Lab%209%20Fall%202006%20Diodes.pdf).
Datasheet: 1N4006. Reference: Sedra/Smith ch. 4.

Schematics file: `diodeSchematics.ts`. The `diode` symbol exists in `circuit.ts`.

| lesson | what the student sees |
|---|---|
| `ee.diodeIV` | The i–v curve: exponential, with the 0.7 V knee. Sweep v across it with a dot; the current counter reads nanoamps then milliamps. Then the constant-voltage-drop model drawn over it as the straight-line approximation everyone actually uses. |
| `ee.halfWaveRectifier` | The brief that started issue #121, done right: AC in, the diode lit (current shown) only during the positive half-cycle, the output following the input minus 0.7 V and then sitting at zero. Scope: input and output on one time axis, the missing half visible. Transfer view: the i–v curve with the dot riding it. |
| `ee.fullWaveAndSmoothing` | The bridge: both half-cycles delivered, output frequency doubled. Then a smoothing capacitor across the load: ripple, with the ripple amplitude read live and the formula V_r ≈ I_L/(f C) beside it. |

## Integration order

Batch 1: Tiers 2 and 5 (independent). Batch 2, once Tier 2 has landed on `main`: Tiers 3
and 4, which reuse `opAmpSchematics.ts`. Each tier is rebased onto `main`, `npm run
verify` passes on the combined tree, the tier's frames are rendered once more on the
integrated build, and its caveats are appended to `docs/EE230_LESSONS.md`.
